## 怎么挡的

只挡这次进程。本进程起了一个只听 `127.0.0.1` 随机端口的 HTTP 代理，服务和它拉起的 grok 把 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`（含小写）指到这个代理，并设置 `NODE_USE_ENV_PROXY=1`。`NO_PROXY` 只有 `localhost,127.0.0.1,::1`。

代理对下面 9 个域名（含其子域）的 CONNECT 直接回 `403`，不往外拨：

- ingest.t3.codes
- relay.t3.codes
- prod-a1.t3coderelay.com
- prod-b2.t3coderelay.com
- app.t3.codes
- nightly.app.t3.codes
- latest.app.t3.codes
- t3.codes
- clerk.t3.codes

其余目标转给当时已经启用的用户代理（回环地址）。没有改系统 hosts，没有改用户代理的开关、服务器和例外。验完关掉这个进程代理。

开跑前的自测：

- `CONNECT ingest.t3.codes:443` 得到 `HTTP/1.1 403 Forbidden`
- `CONNECT api.x.ai:443` 得到 `HTTP/1.1 200 Connection Established`

另外试过按程序给 `node.exe` 和 `grok.exe` 加 Windows 出站拦截规则。`New-NetFirewallRule` 返回拒绝访问，两条都没建成。结束时按这两个名字再删了一次，机器上没有留下这组规则。

hosts 文件和用户代理（是否启用、服务器、自动配置、例外）的哈希，开跑前和结束时相同。`netsh winhttp show proxy` 的输出哈希在结束那一刻不同；脚本只执行了 show，没有 set。结束后再读，哈希回到开跑前的值。

服务日志有一行：`T3CODE_OTEL_SDK_DISABLED is set, so no telemetry is exported, whatever configured it`。追踪日志里没有这 9 个域名。

## 核心功能

智能体是 grok，模型 `grok-build`。线程 `ec36d781-bd0b-4195-88ac-0ca94931ba0e`。工作区策略是独立 worktree（`baseRef` 为 `HEAD`，`startFromOrigin` 为 false）。共享的 root 工作区会拒绝恢复文件，服务返回 “File restore requires an isolated worktree”；文件回退走它支持的独立 worktree。

| 项 | 结果 |
| --- | --- |
| 开会话 | 回合 `completed`，没有报错 |
| 收发消息 | 用户消息发出；助手先说明要建文件，随后回复 `GATE2-DONE` |
| 改文件 | worktree 里的 `gate2-edited.txt` 内容为 `GATE2-EDITED` 加换行 |
| 检查点回退 | 回到序号 0。回退前文件在，回退后文件不在。序号 1 的检查点变为 `stale`，回合变为 `rolled_back`，`rollbackFailure` 为空 |
| 本地 git | 回退之后写入 `gate2-commit.txt`。刷新状态看到这个未提交文件。提交动作收到 `action_finished`，最新提交 `be3e2900e778a8a259ddc072945cba20e8c5bf2f`，说明是「记录关二验证的本地提交」。提交后 `git status --porcelain` 为空 |
| 终端 | 在该 worktree 打开终端，写入 `echo GATE2-TERM`。输出里先出现这条命令，下一行是 `GATE2-TERM` |

回退请求发出 60 秒后，文件和回合状态已经是回退后的样子，线程上的 `rollbackRequestId` 仍在。没有因此再发一次回退。
