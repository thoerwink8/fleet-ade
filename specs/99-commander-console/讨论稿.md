# 指挥台：指挥会话、子会话动态、派活规矩（2026-11-18，已定）

状态：已定。对照的代码是 `origin/main` `28b7803`。本稿只写设计，不改产品代码。视觉原型另做，不进仓。

守的业务：人整天只跟一个指挥会话说话；这个会话派子会话干活、看它们现在的做法、走偏就纠正、验收后由人合并。子会话写代码时常常不说话，人要不用点进每一条会话就能看见它在做什么。

## 二、对原方向的采纳、修正和驳回

原方向：指挥会话是标出来的普通会话，侧栏置顶，子会话成树；右侧一栏看动态；「现在在做什么」分事件一层和模型一层；走偏也通知指挥会话里的 agent；跨机走摘要；三端都要能看能纠正。

采纳：

- 不新建中心页。指挥是会话上的标记，不是新的一种线程，也不是主导航里的新首页。
- 右侧栏看一行摘要，点开才看目标和最近动作。正文、diff、命令输出留在完整会话里。
- 第一层不调模型。第二层只在点开、或步数到了、或第一次跨过沉默线时算，输入没变不算第二次。
- 跨机不订全文。摘要进同一栏，点开才走现有的会话订阅。

修正：

- 「一个指挥会话」只对机群里领单的那一任成立。一个环境里可以有多条标成指挥的会话（人有时按仓分开聊）。其中只有本任期那一条能领单、能派已领的活。其余的只能派随手活。这和 #95「不按仓拆协调者」一致，避免把驳回过的「每仓一个协调者」从后门放回来。
- 协调者和指挥会话不是同一个东西。协调者是管租约的那台机器上的角色；指挥会话是人说话的那条会话。本任期的指挥会话住在协调者所在的环境里，消费租约，自己不是租约表。一个任期最多一条本任期。换任期才新开下一条，带上交接摘要和旧会话链接，任期号加一。同一任期里可以把另一条标成接替：旧的去掉本任期，任期号不变。#95 已经否了「继续操作旧机器上的同一条」和「把旧会话复制过去」。
- 子会话挂在父下面是现有行为，普通会话本来就有。本稿不另造第二棵树，也不只给指挥加一层。再深的不进动态栏。指挥标记多的是置顶和右侧栏。
- 走偏进的是指挥会话自己的通知，不写进结束收件箱。收件箱只记运行终态，塞进走偏会把两件不同的事合成一张表。
- 自动巡检默认关。一次走偏或一次沉默最多叫起一次，不按钟重复。见第六节。
- 子会话不是新开一条顶层会话。挂在指挥下面、进动态栏的是已有的委派（`delegate_task`，可以带它已有的工作树隔离）。`t3_thread_launch` 和 `create_threads` 开的是顶层会话，不进动态栏的状态机。若指挥会话还是开了顶层会话，侧栏在它下面多一行链接，标明是另开的会话。不禁用那两个工具。

驳回：

- 单独的指挥中心页，或会话顶部再嵌一整页。人和原方向都已经觉得不对。动态栏是这一页上的一栏，不是第二产品。
- 每台机器各设一个指挥，活先交给对方的指挥再往下派。多一次转述，两套回报，和「只有协调者写租约」冲突。本机指挥经已经连上的远程环境直接委派子会话。
- 把模型名字写进程序。用哪一个，只出现在分工表的格子里。
- 用 `t3.json` 或每仓一份技能文件当派活规矩。技能文件是给人看的操作说明，产品里对应的是设置：一张表加一份守则。

删掉整层的备选：如果右侧栏够用，侧栏里那棵子树就是同一批行的第二份。代价是不点进指挥会话就看不到谁在跑。不采纳。现有委托任务已经挂在父会话下，拆掉会让父子有两种呈现。

## 三、指挥会话

成为指挥：在会话菜单、命令面板、快捷键里「标成指挥」。反向是「取消指挥」：标记和右侧栏消失，置顶取消。子会话仍按现有规则挂在下面，不因为取消就散开。取消的是本任期那一条时，不自动把别的指挥标记升上来；这一任期暂时不能领单，租约还在。人再把一条标成接替才接回来。第一期没有本任期，取消只是去掉标记。
第三期才有的「标成接替」和取消本任期是不同的动作。接替是同一次：旧的去掉本任期，新的标上，任期号不变，不会两条同时是。取消只去掉标记，不释放机群租约（租约是机器的，不是这条会话的）。之后要领单，人再做一次接替。不自动挑另一条。

一个环境可以有多条。侧栏里凡是标了的都排在普通会话前面，按最近有动静排序。机群接上之后，本任期那一条再靠前。本任期不在侧栏写字，页头写「本任期 · 第 N 任」。第一期没有机群时，没有「本任期」。

它的状态不另存，由子会话推出来，页头只显示最要紧的一层：这条指挥会话自己的环境连不上 > 等你拍板 > 正在派出 > N 个在做 > 空闲（空闲不额外写字）。等你拍板包括等回答、等批准、未处理的走偏、失败、超时、某一行连不上、等你决定合并。有这些事时页头不会显示空闲。某一行连不上，不停这条会话的输入框；只有这条指挥会话自己的环境不可达，输入框才停用。

和普通会话的差别只多这三样：标记、置顶、右侧动态栏。侧栏里的子会话是现有的父子呈现，不是指挥专有的树。对话、输入、已有的分支和 PR 详情不变。

住在哪个项目下：创建时仍选一个项目，和今天一样。派到别的仓靠远程环境和机群服务，不受这个项目的目录限制。这是 #95 已定的，不另做「一个会话绑定多个仓」。

## 四、子会话状态

状态由已有投影推出来。除「沉默太久」「超时」「可能走偏」「连不上」「合并状态未知」是这一栏加的判断，其余都不新造运行状态。沉默和超时在服务端算，不在每个客户端各跑计时器，所以栏、手机和 `t3_command_children` 看到的是同一句。沉默的条件是：还在跑，最新一条不是还没结束的命令，也不是等你回答或批准，并且超过设置里的分钟数没有新的回合条目。长命令那一行写「命令还在跑」，等你就写「等你」，这两类不算沉默，也不触发自动巡检。时限从这次运行开始算，排队的时间不算。

| 状态            | 从哪来                                                                                      | 人能做什么                                               |
| --------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 排队            | 子会话已建，运行还没开始；或下一条已经排上、当前这条还没动                                  | 打开、取消这次排队                                       |
| 在跑            | 会话状态是在准备、启动或运行                                                                | 纠正、停止、打开                                         |
| 沉默太久        | 在跑，最新一条不是还没结束的命令，也不是等你，并且超过设置里的分钟数没有新条目。默认 3 分钟 | 纠正、停止、打开。行上另写时长                           |
| 可能走偏        | 第二层说走偏，且这次输入还没被标成误报。第一期没有这一层，就不会出现                        | 让它改、标成误报、打开                                   |
| 等你            | 已有的等回答或等批准                                                                        | 去回答或批准（沿用现有卡片，不在栏里重做一份表单）、打开 |
| 已完成          | 运行已完成，没有挂上的 PR，且角色不是写码                                                   | 打开                                                     |
| 没有 PR         | 角色是写码，运行已完成，没有挂上 PR。算进「要你看」                                         | 打开                                                     |
| 等验收          | 挂着一个仍开放、还没合并的 PR                                                               | 打开、看 PR                                              |
| 已合并          | 这个仓已经在跟踪的 PR 是已合并。不另做「我确认合并了」                                      | 打开                                                     |
| PR 已关闭       | PR 关了且没合并。不算已合并，也不停在等验收。算进「要你看」                                 | 打开、看 PR                                              |
| 合并状态未知    | 有 PR，但查询失败、没权限或被限流。不把未知说成等验收或已合并                               | 打开、重试查询。不挡打开 PR                              |
| 已中断 / 已取消 | 运行终态里的中断和取消                                                                      | 打开。默认折进「已结束」                                 |
| 失败            | 运行终态是失败。不折进已结束，页头算进「要你看」                                            | 打开                                                     |
| 超时            | 在跑，但过了这一次的时限。时限从运行开始算，排队不算。默认只改这一格的字，不杀进程          | 纠正、停止、打开。页头算进「要你看」                     |
| 连不上          | 这一行的执行环境摘要断了，不是整条指挥会话不可达。上一句留着，但标明不是刚刷新的            | 不能纠正、不能停止，直到恢复。输入框仍可用               |

「已合并」不是结束收件箱里的词。收件箱只知道运行结束和提交号。合并以这个仓已经在跟踪的 PR 状态为准。查不到就停在「合并状态未知」，不猜。

## 五、「现在在做什么」

### 第一层，不调模型

每个子会话在自己的环境里留一行派生结果，挂在已有的会话壳上，不新开事件流。只在回合条目或运行状态变了时重算。推给指挥页的是这一行，不是条目本身。

| 最新情况                           | 一句                                                     |
| ---------------------------------- | -------------------------------------------------------- |
| 正在启动，还没有条目               | 正在启动                                                 |
| 最新是改文件                       | 在改「文件名」                                           |
| 最新是跑命令                       | 在跑「命令第一行」，超过 80 字截断                       |
| 最新是查文件或查网页               | 在查「关键词」，没有关键词就写「在查代码」或「在查网页」 |
| 最新是方案步骤                     | 在做「当前步」                                           |
| 有等回答                           | 在等你回答                                               |
| 有等批准                           | 在等你批准一条命令                                       |
| 在跑，但只有回复、这段时间没有工具 | 在写回复                                                 |
| 运行完成且 PR 未合并               | 等验收                                                   |
| 失败、中断、取消                   | 用第四节的短字，不再编一句                               |

点开才多带：目标、别碰（都是派出时存下的短文本）、最多 5 个文件名和增删行数、最近一条命令的第一行、分支、PR 号。文件 diff 和命令输出不进这一行；点「打开完整会话」才走现有订阅。

沉默不改写上一句，只叠加「没动静」。

### 第二层，模型摘要和走偏

走分工表里对应的行。那一行关着，或没配模型，就完全不调用。

什么时候算：

- 人点开这一行，且缓存对不上；或
- 在跑期间，改文件和跑命令合计又满 N 次（默认 20）；或
- 这一次运行里第一次跨过沉默线。

不按时钟重复算。

喂进去的只有：目标、别碰（合计截到 2000 字）、第一层那一句、最多 5 个文件名、最近命令的第一行、增删行数合计。不喂命令输出，不喂 diff 正文，不喂对话。

产出两句以内：在做什么；有没有偏离目标和「别碰」。缓存键是这份输入的摘要。键不变不调用。

误报：人点「这不是走偏」，记下这个键。同一个键不再提醒。输入变了（改了别的文件、或目标改了）可以再提醒。

失败：留下上一次缓存（没有就空着），界面写「摘要没写成」，可以重试。子会话该跑继续跑，纠正和停止不受影响。

## 六、给 agent 的面

一个服务方法列出某条指挥会话的直接子会话。字段和栏上的一行相同，另加目标摘要（截到 200 字），不含正文、不含别碰全文。一页 50 条，响应里带下一页标记；没有下一页就是空。不一次灌进上下文。

MCP 只加只读的一枚：`t3_command_children`（可带上一页给的标记）。纠正仍用已有的 `t3_thread_send`，但服务先看运行态：不是正在跑就拒绝，界面写「这条已经停了」，不记成「你直接纠正了」。这一期不加「重新开跑」。停止委托来的子会话走已有的取消任务，不走 `t3_thread_interrupt`（那条留给非委托的普通会话）。打开仍用读会话。不把栏上的操作再包一层。

更正（2026-11-19）：发消息只拒已取消、已打断、已回滚的委托子会话；已完成、失败的仍可补发，保留 main 已有的 follow-up 功能。

走偏和沉默不进结束收件箱。收件箱继续只记本机运行终态和提交号，指挥会话要终态时读它，不改它的职责。

自动巡检：分工表里一行，默认关。打开之后，进入一次走偏或一次沉默时最多发一条短消息。这个状态还在也不再发。输入变了、形成新的一次走偏，才再算新的一次。不按「人有没有点开」来决定叫不叫。等你和「命令还在跑」不叫。已完成、失败、等验收、排队也不叫。

辅助环节的执行都进同一个入口 `CommandAssist.run(环节, 输入)`：查表，关着就返回「跳过」，调用失败或超过固定的 15 秒就返回「没做成」并留下原因。这 15 秒不做成设置。调用方不许把这个结果当成失败，也不许在主路上空等：派活先发出去，口语整理来不及就用原话，后到的结果只补在行上；交回核对在运行结束后异步写到行上，不挡住收件箱和打开 PR；点开一行时摘要可以等这 15 秒，到点就显示「摘要没写成」。新环节是这个入口加一个已知环节号，加上表里的默认行。不加在发消息、提交事件的主路上。未知的环节号在设置里留着（以后的版本认得），当前版本不跑。

指挥会话里的 agent 对这张表和守则只有读。不新增写入工具。现有的通用设置写入若能改到「指挥」这一节，这一节排除在外。改表只在设置页，或页头打开的同一节，由人来改。

## 七、算账

一行摘要按 400 字上限估计，约 1 KB。栏上只订阅这些行。

同一行最多每 2 秒推一次；状态变成「等你」「失败」「连不上」时立刻推。2 秒是固定的，不做成设置。没有变化不推。

人开着指挥页、10 个子会话都在忙：最多约 10 × 30 次/分钟 × 1 KB ≈ 300 KB/分钟，并且只在这一页开着时发生。3 台机器不改变这个数：每台机器把自己的行算好，指挥页仍然是这么多行，不是 3 份全文。

点开一行才增加一条现有的会话订阅，关掉详情就退订。不点开就不为那个子会话订全文。

模型调用（辅助行都开着、按默认触发，粗算一天）：

| 环节                 | 一天大概几次                                               |
| -------------------- | ---------------------------------------------------------- |
| 起名（已有）         | 每个新会话 1 次。一天十来条会话就是十来次                  |
| 摘要 + 走偏          | 每个在跑的子会话几次到十几次。10 条活、每条 6 次，约 60 次 |
| 交回核对里的那次模型 | 每条活结束 1 次，约 10 次。对得上号的部分不调模型          |
| 口语整理             | 人点一次算一次，不会每次发言都算                           |
| 交接摘要             | 换任期或人要求换指挥会话才算，一个月几次                   |
| 每日汇总、沉默原因   | 默认不跑，是 0                                             |

合计大约一天一百次以内的短调用，输入是截断后的摘要，不是会话全文。关任何一行，那一行就是 0。

读的量跟栏上的行数成正比，不跟会话有多长、机器有多少成正比。

## 八、派活规矩放哪，什么不写死

三层，后一层盖前一层，只盖写了的格子：

1. 环境默认。装好就能用，人没改过就是下面这套。
2. 这个仓的项目设置盖过。沿用现在的项目盖环境，不新做一种「仓配置文件」。
3. 单次派活。只在这一次的派出参数里写模型和时限，不写回表。

一张表的两截：

- 「派谁做」：写码、复查、只读查看、出方案、指挥会话自己。格子是已配置的 provider、模型、档。空着就用这个仓现有的默认模型（`defaultModelSelection`）。子会话走已有的 `delegate_task`（挂在父会话下；工作树隔离用它已有的参数）。不走 `t3_thread_launch` 或 `create_threads`：那两个开的是顶层会话，不挂在指挥下面。人若是要一条自己能聊的新会话，仍用那两个，那条出现在普通列表里，不进动态栏。守则要求派活走委派，但不禁用这两个工具。
- 「辅助」：第九节里决定要做的每一行。格子是开或关、provider、模型、档。空着的模型用 `textGenerationModelSelection`。关了就不调用。

表外只有三个数，和表存在同一处：

- 多久没动静算沉默。默认 3 分钟。
- 同时派出的上限。默认空，不限制。填了数，数的是这一条指挥会话正在跑的和排队的直接子会话，加在一起。超过就这一次委派直接拒绝并说明已满。不另设一个排队上限。多条指挥各自数，不做全机的容量测量。
- 单次时限。默认空。填了，到点把行标成超时。另有「到点就停止」，默认关。

表由服务执行，不靠指挥会话里的 agent 记得照做。委派上有一个可选角色：写码、复查、只读、出方案。没写按写码。父会话是指挥、这次又没自己写模型和档时，服务按目标仓项目设置里对上的那一格填上（项目盖过那个仓所在环境的默认）。这次写了就只覆盖这一次。并发到了上限，同一次委派直接拒绝并说明已满。目标、别碰、要跑的测试是这次委派上的可选短字段。目标与别碰各截到 1000 字，测试命令按行截到 20 行。没写目标时，行上用正文前 200 字；没写别碰就显示「没有写别碰」。不新开一个派出工具。

「指挥会话自己」这一格不填到子会话上，用的是宿主项目的那一格，不是目标仓的。它只决定这条指挥会话下一回合用的模型和档。空着就保持这条会话已经在用的，不因为标成指挥就换模型。
委派被接受时，把这次用到的模型、档、时限和守则记在这次委派上。之后改设置，不影响已经接受的这一次。

指挥守则是同一处设置里的一段文字。环境一份，仓可以盖过。设置页和指挥会话页头打开的是同一份。恢复默认就是删掉这一层盖过的值，回到环境或内置原文。

内置原文（人没改过时，指挥会话的说明里带上这一段）：

- 同一件活已经有子会话还在做，就发回那一条，不新开。
- 一件活一棵工作树、一条分支。分支名用这个仓已有的命名设置。已经领了单的，用那张单定下的那条分支。
- 交代写全：做成什么样、怎么算做完、别碰什么、要跑哪些测试。没写的不替它扩大范围。
- 子会话不合并。
- 回报里要有做到哪、PR 号、头提交、核对命令的真实结果、没做的和原因。指挥会话核对这几项，不照抄回报里的句子。
- 过了沉默时限先看它卡在哪，不要因为没说话就再派一个。
- 时限到了只标超时，除非这次交代写明到点就停。
- 子会话不再往下派。若还是派了，动态栏不单列孙会话，只在那条直接子会话的行上写「它还派了 K 个」。点开完整会话才看下层。第一期不做下钻。
- 已领的单只从本任期指挥会话派。不领单的随手活可以在本机做。

这段是从现在的派活做法抽出来的，不是哪一份外部说明的原文。

故意不做成设置的：

| -------------------------- | ---------------------------------------------------------------------------------------------------- |

| 每个环节一份自己的提示词   | 和「一处配置」相反。例外是已经存在的起标题说明、复查说明，它们有自己的评测，留在原处，不并进指挥守则 |
| 侧栏展开几层               | 固定一层                                                                                             |

## 十、跨仓、跨机器、跨设备

结论先写在这里。

指挥会话挂在一个项目下，但能给别的仓派子会话。栏和侧栏按仓筛选。它不「属于一个仓」到别的仓就看不见。
关系是这样：

```text
人（本机 / 手机 / 另一台电脑的浏览器）
        │ 打开的是同一条本任期指挥会话
        ▼
本任期指挥会话 ──住在──► 协调者那台机器上的环境
        │                         │
        │ 直接委派（本机或远程环境） │ 租约表在这台机器上（#95）
        ▼                         │ 指挥会话不是这张表
子会话（挂在这条会话下）◄─────────┘ 只有协调者写租约
        │
        ▼
动态栏里的一行摘要；点开才向执行环境要正文

同机其他「指挥」标记：能派随手活，不能领单
另一台机器上的指挥标记：看得到摘要，不能派已领的单
换主力机器：新任期，新开一条指挥会话，带交接摘要和旧会话链接
```

一台机器上可以有多条指挥会话。和 #95 的协调者关系：

- 协调者 = 这一任里持有租约表的那台机器。一个机群一个。
- 指挥会话 = 人说话的会话。本任期那一条开在协调者所在的环境里。
- 二者不是同一个对象。指挥会话挂了，租约表还在。一个任期最多一条本任期。换任期才新开下一条并换号。同一任期里把另一条标成接替，旧的去掉本任期，任期号不变，不是换任期。
- 同机上其他标成指挥的会话不是第二个协调者，不能领单。

活要在另一台机器上跑：由本任期指挥经远程环境直接委派子会话。不交给那台机器上的指挥再派。

|      | 直接委派                                 | 交给对方指挥                                                     |
| ---- | ---------------------------------------- | ---------------------------------------------------------------- |
| 好处 | 一条回报线；租约仍是协调者写；少一次转述 | 对方指挥更靠近那台机器的本地规矩                                 |
| 坏处 | 指挥会话的 agent 必须使用已有的远程委派  | 两套指挥可能各派一次；对方那条会话不一定是本任期                 |
| 取舍 | 采用。就是上图的「直接委派」             | 不采用。对方那条若是上一任，只读；若只是本地标记，本来就不能领单 |

两台机器都有指挥标记时：

- 互相能看见的，是 #95 那路摘要（状态、标题、一句进度、分支、提交号）。不是对话正文。
- 点开才向执行环境要详情。要得成要看现有的环境授权。
- 只有本任期那一条能派已领的活、能替那张单纠正方向。另一条可以把一句话发给本任期会话（沿用给会话发消息，要有那条会话的写权限），这是在请求，不是在派活。
- 纠正某个子会话，要有那个子会话所在环境上的写权限。没有就只能看。不新做角色，沿用现有的会话写入范围。

换设备（手机、另一台电脑的浏览器）：打开的是同一条本任期指挥会话。远程和隧道只改路由，不另复制一条。

换一台机器当主力：走 #95 的任期交接。新机器上新开一条指挥会话，第一条放交接摘要和旧会话链接。不是同一条会话。#95 否掉的两种（接着操作旧机器上的那条、把事件复制过来）这里同样不采用。

和 #95 没有要翻案的冲突。容易混的一点已经按 #95 收紧：人可以在本机多开几条指挥标记，但机群里领单的入口仍然只有本任期那一条，不是每仓一条。

## 十一、界面需求清单

视觉按这一节做。字号、颜色、间距跟界面打磨那一单，本节不规定。低保真线框不作为本稿的附件。

不是新的中心页。是一个被标成「指挥」的普通会话页，多两块：侧栏里置顶并挂一层子会话；右侧常驻「子会话动态」。普通会话的对话、输入框、已有详情保留。取消标记后这两块消失，会话还在。

### 侧栏

- 标题同普通会话。一枚「指挥」。本任期再加「本任期 · 第 N 任」不放侧栏，放页头。
- 标成指挥、取消指挥：会话菜单、命令面板、快捷键都要有。取消不删会话、不停止子会话。钉住仍是现有的钉，和指挥标记互不代替。
- 子会话只挂直接派出的一层。行上是标题和状态短字；等你看的要能认出来。排序和右侧栏同一套。点行打开完整会话，不在树上纠正。没有子会话时不占「暂无」行。
- 多条指挥都排在普通会话前，按最近动静。本任期在最前。

### 会话页主区

和普通会话相同。页头标题旁是「指挥」标记，点开能取消，也能进设置里的同一节。本任期在页头写「本任期 · 第 N 任」，有上一任就给链接。主区不重复放子会话墙。

页头状态字：空闲不额外写；正在派出；「N 个在做」；「M 件要你看」；这条指挥会话自己连不上（只有这时输入框停用）。某一行连不上只算进「要你看」，不停输入。叠在一起只显示第三节那个优先级里最要紧的一个。

### 右侧栏

三种都要能用：收起、展开列表、点开一行。

栏顶：标题、计数「2 在做 · 1 要你看」（全空闲不写）、收起。收起后留下竖条，竖条上仍有「要你看」的数量。按仓筛选；只有一个仓不显示筛选。

一行只放：标题、状态短字、第一层那一句、仓名（同仓连续只第一行写）、沉默时长（只有沉默才写）、单号（有才写）。不放正文、diff、命令输出。

点开在栏内展开：目标、别碰（没有就写「没有写别碰」）、第一层那句、第二层摘要（关了不出现；在算写「正在写摘要」；失败写「摘要没写成」和重试）、走偏（没有不出现；有则「让它改」「这不是走偏」）、最多 5 个文件名和增删行数、最近命令第一行、分支、PR 号。

操作：纠正、停止、打开完整会话。已合并不再放「标记已合并」。
不是正在跑的行（含等验收、已完成、已合并、失败、已取消）两个纠正动作都不可用，行上写「这条已经停了」。不把话发出去假装它还听得见。停止也一样，只对还在跑的可用。委托来的子会话，停止走取消任务，不走普通会话的中断。

更正（2026-11-19）：发消息只拒已取消、已打断、已回滚的委托子会话；已完成、失败的仍可补发，保留 main 已有的 follow-up 功能。

纠正拆成两个动作：「直接告诉它」（发给子会话），「让指挥转达」（先发进指挥会话）。发出后行上记「你直接纠正了」或「已交给指挥」，不把正文抄进每一行。

排序：等你拍板（含失败、超时、这一行连不上、可能走偏）、沉默太久、在跑、排队、等验收、已完成、已结束。失败、超时、连不上不折进已结束。已中断、已取消、已合并折成「已结束 N」。同组里最近有动静的在上。直接子会话若又派了下层，行上写「它还派了 K 个」，不单列。

空状态：栏还在。一句「还没有派出的子会话」，操作「去写交代」把焦点放进输入框。

短字：排队、在做、命令还在跑、没动静（带时长）、可能走偏、等你、已完成、没有 PR、等验收、已合并、PR 已关闭、合并状态未知、已中断、失败、已取消、超时、连不上。可能走偏、等你、超时、失败、连不上、没有 PR、PR 已关闭压过「在做」。连不上时不把旧句说成刚刚刷新。

### 设置

只有一节「指挥」：第八节的表，加指挥守则。表下就是那三个数和「到点就停止」。每行能恢复该行，页底能全部恢复。守则标明生效的是环境还是这个仓。单次改模型或时限不在这页，在派出的那一次上改。

这一页不放：推送间隔、状态词映射、动画、每个环节一份提示词、租约。

### 跨机时多出来的

行上写仓名和已有的环境名，不写地址。点开跨机行，摘要用栏里已有的；打开完整会话才去连。本任期以外的指挥会话，栏里没有「派这张已领的单」。

### 三端

网页和桌面同一页。手机没有常驻右栏：页头一颗「N 在做 · M 要你看」，点开全屏列表，再点进行进一层。列表和点开的字段与网页行相同，纠正和停止的结果写回这一行，不另做确认页。手机不要求侧栏子树和网页一样；现有列表挂不了子行就不新做一套手机树。手机设置里表改成一行一种活，不横滚。命令面板三端都有「子会话动态」「标成指挥」「取消指挥」。快捷键只在网页和桌面。

远程和隧道不换布局。连不上就显示连不上。没写权限时行还在，纠正和停止变灰，并说明缺的是对那个会话的写权限。

### 不要做的界面

- 不要新的「指挥中心」导航。机群看板是 #95 的页。
- 不要在对话里再嵌一块卡片墙。
- 不要持续动画和按秒跳的计时。
- 不要把输出、diff、思考过程放进栏里。
- 不要给每个状态做一套颜色。只区分「要你看」和普通。

原型至少覆盖：混合状态的展开栏、点开走偏行、收起、空状态、页头空闲和等你拍板、设置表里有一行是关的、手机列表和点开。假数据用 #99、#98、#95、#100、#96 和分支 `local/99-commander-console` 这种真实形状，不用「foo」。

第一期，单机，不依赖机群，不调辅助模型。

## 十三、拍板结果与实施单

2026-11-18 由创始人授权指挥官拍板，八条全部按甲定。没采用的备选各留一句原因。

1. 一个环境几条指挥会话：多条可以，领单只认本任期一条。不限制为一条：人有时按仓或按事分开聊。不每仓强制一条：和 #95 不按仓拆协调者冲突。
2. 纠正怎么发：展开里两个动作，直接告诉子会话，或让指挥转达。不只放次级：两种时机都常用，收进次级会找不到。不只准经指挥：已经想好怎么改时不必再绕一层。
3. 走偏默认开不开：默认开、可关，误报时同一次输入不再响。不默认关：走偏是指挥台要守的核心风险。不只做沉默：沉默和走偏不是一回事。
4. 指挥会话里的 agent 自己巡检：默认关；打开后同一次走偏或沉默最多叫一次，不按钟重复。不默认开：避免每个异常都往指挥会话里发消息。不永远不叫：需要时留一条入口。
5. 跨机派活：本任期经远程环境直接委派。不交给对方机器上的指挥：多一次转述、两套回报，且对方不一定是本任期。
6. 时限到了：只标超时，另给一个默认关的「到点就停止」。不到点就杀：长测试或慢机器会被误杀。不设时限字段：指挥需要看得见「过了该有动静的点」。
7. 每日汇总：不做。栏和指挥会话已经是当天的账，再发一条是重复。要做时复用交接摘要那个环节，不单开定时任务。
8. 侧栏子会话：沿用现有父子呈现，指挥只加置顶和右栏。不只给指挥加一层：普通会话的委托本来就挂在父下面，拆掉会有两种父子行为。

## 十四、业界对照

两处独立来源，只取结构，不取界面皮肤，也不把别人的配置文件格式搬进来。

- Claude Code 的子代理：同一种活可以单独指定模型，项目一层、用户一层，能关掉某一类。总览是一行一个后台会话，而不是把每个会话的正文铺开。见 [Create custom subagents](https://code.claude.com/docs/en/sub-agents)。
- 把多个编码代理放在一处看的做法，同样是一行一个、状态为主，点开才看细节。见 [The fleet view](https://agentinterface.app/guides/multi-agent-supervision-the-fleet-view-arrives) 和 [看到所有代理在做什么](https://collidemcp.com/blog/see-what-all-ai-coding-agents-are-doing)。

取：一行一个工人；模型按活的类型配，不写死；项目盖过环境。不取：再做一个独立的总览产品、每种活一份提示词文件、组织级下发的代理目录。

- 等你超过时限仍应叫沉默（gpt）。不收。等你已经算进「要你看」，再叫沉默会把「在等你」说成「它卡住了」。
- 孙会话要有明细和停止（gpt）。不收。第一期不做第二棵树。栏上只计数，停止在完整会话里走现有的取消。
- 写码却没有 PR 不能叫已完成（gpt）。收。角色是写码、跑完、没有 PR，短字是「没有 PR」，算要你看。不是写码的，没有 PR 仍是已完成。
- 关着的那一份不该先生成再丢掉（kimi）。收。提示词只要求开着的。一句没写成不盖掉另一句。不另做版本号。
- 设置要在委派时拍成快照（gpt）。收。见第八节。不另存一份环境快照。
- 取消本任期应释放租约，或拆成暂停和卸任（gpt、kimi）。不收。租约是协调者那台机器的，不是这条会话的，取消标记不放租约。接替是同一次动作，人自己做，不自动选。不新做两种卸任。
- 点开不算处理完，纠正失败还应再提醒（gpt）。不收再提醒。进入该状态时最多一条，之后不再发。纠正没被接受，行还在，人不靠第二条消息才看得见。
- 测试基准还要存工作目录、参数和环境（gpt）。不收。基准就是派出时的命令文本，目录就是那棵工作树。
- 排队不计并发，队列会堆满（gpt、kimi）。收。正在跑的和排队的加在一起，仍是一个数，不另设排队上限。排队本身不因此开始算时限。
- 15 秒应能按仓改（gpt）。不收。和 2 秒推送一样，是上限不是偏好。
- 连不上被当成失败（gpt）。不收。稿里本来就是两种状态：连不上不是失败终态。
- 沉默会打到已完成的行上（kimi）。收。只有还在跑、且不是等你、也不是命令还在跑，才算沉默。已完成、失败、等验收、排队不算。见第四节，本来就是这个条件，这里写明确认。
- PR 关了却没合并，会永远等验收（kimi）。收。等验收只对仍开放的 PR。关了且没合并，短字是「PR 已关闭」。
- 手机列表只有按钮、没有状态和结果（gpt）。收。手机行的字段与网页相同，操作结果写回这一行。
